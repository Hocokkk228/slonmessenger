# SLON Messenger — контекст проекта

## Что это
Веб-мессенджер SLON (HTML/CSS/JS), хостится на GitHub Pages. P2P-сигналинг и
синхронизация через Firebase Realtime Database (проект `slon-376b4`,
регион europe-west1). Firebase SDK — **compat 8.x** (не 10.x — в 10.x
`db.ref()` не работает как обычный метод, был проверен баг, откатились на 8.x).

## Структура файлов
```
index.html          — разметка
style.css           — все стили
js/
  core.js           — состояние (let-переменные), утилиты (toast, saveAll,
                      loadStorage), константы (THEMES, BG_COLORS и т.д.),
                      весь top-level код (IIFE, boot-последовательность)
  firebase-core.js  — signaling, presence, auth-обвязка Firebase
  auth.js           — регистрация/вход/сессии (пароли хешируются SHA-256,
                      хранятся в Firebase auth/{username}/hash)
  chat.js           — сообщения, пины, контекстное меню чата
  media.js          — голосовые, слонкружки (video circles), файлы
  calls.js          — 1-на-1 звонки WebRTC (самый крупный модуль, 47KB)
  group-calls.js    — групповые звонки
  voice-rooms.js    — голосовые комнаты
  groups.js / channels.js — группы и каналы
  admin.js          — бан/премиум/слонгалочка/админ-консоль
  profile-ui.js     — профиль, темы (19 тем: 9 free + 10 Premium), обои
  sidebar-ui.js     — сайдбар, хедер чата, глобальный поиск
  wizards.js        — визарды создания группы/канала (многошаговые)
  ai.js             — AI-ассистент через Hugging Face API
  saved-favorites.js — Избранное (заметки для себя)
  misc.js           — уведомления, экспорт данных
```

Все файлы — обычные `<script src="">` (НЕ ES-модули), делят один
глобальный scope через `window`. Порядок загрузки в `index.html` важен:
`core.js` должен идти первым (там объявления state-переменных).

## Ключевые архитектурные решения
- Локальный notepad "Избранное" (`chatHist.saved`) хранится в **отдельном**
  ключе localStorage (`sl_u_{username}_savedMsgs`), не в общем `chatHist`
  блобе — это защищает от обрезки при переполнении квоты localStorage
- Медиа (фото/голосовые/видео) кладутся в IndexedDB, не localStorage
- `_fbConns{}` — глобальный флаг "в Firebase-режиме ли мы", не per-peer
- Каналы/группы синхронизируются между устройствами одного аккаунта через
  Firebase (`user_channels/`, `user_groups/`)

## Известные грабли (не наступать повторно)
- **Никогда** не делать `$('chActs').innerHTML = '...'` — это разрушает
  постоянные кнопки (search/call/dropdown) навсегда. Всегда скрывать/
  показывать через `.style.display`, не переписывать innerHTML контейнера
  с переиспользуемыми элементами.
- HF API-токен лежит открытым текстом в `ai.js` — если репо когда-то
  станет по-настоящему публичным (сейчас на GitHub Pages технически уже
  публичен), токен нужно ротировать.
- Top-level код (выполняющийся сразу при загрузке, не внутри функций) может
  обращаться только к тому, что объявлено в этом же или **более ранних**
  файлах. Иначе `ReferenceError` обрывает весь остаток файла и boot —
  приложение висит на «Подключение…». Пример: патч `appendMsg` живёт в
  конце `media.js`, а не в `core.js` (appendMsg объявлен в `chat.js`).
- CSS-переходы на `background` с градиентами не интерполируются гладко —
  используем `opacity`-переходы через `::before`/`::after` псевдоэлементы.

## Стиль кода
- Без точек с запятой на входе экономно, но код в целом с `;`
- Комментарии на русском
- Функции с `_` в начале — внутренние/приватные хелперы
- CSS: тема через `data-theme` атрибут на `<body>`, переменные `--accent`,
  `--bg1/2/3` и т.д. в `:root`/`[data-theme=...]`
